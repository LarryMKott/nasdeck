# 缺陷报告:fnOS 1.2.0701 本地安装 .fpk 时,入口的 gatewayPrefix/gatewaySocket 字段被静默丢弃

> 面向:飞牛官方(fnOS 研发/应用中心团队)
> 报告日期:2026-10-09
> 严重级别:高(统一网关对本地安装的第三方应用完全不可用,与官方开发文档承诺不符)
> 复现包:文末附录(最小复现 .fpk 构建脚本)

---

## 一、摘要

在 fnOS 1.2.0701 上,通过**应用中心 UI 手动安装**或 **appcenter-cli install-fpk** 安装的
第三方 .fpk 应用,其 `ui/config` 中声明的 `gatewayPrefix` / `gatewaySocket` 字段在入口
导入时被**静默丢弃**——PostgreSQL `trim_sac` 库 `entry` 表对应行的这两列为空,
trim_http_cgi 因此永不注册该应用的网关上游,`/app/{prefix}` 路由对一切转发请求返回 404。

**同一声明形态**在系统初始化批量导入(预装应用)与**商店安装**应用上均正常导入。
结果:本地开发/分发的第三方应用无法使用统一网关(含 WebSocket),与
developer.fnnas.com《统一网关》文档描述的行为不符。

## 二、环境

| 项 | 值 |
|---|---|
| fnOS 版本 | 1.2.0701(2026-09-29 安装,测试窗口内无系统更新,`/usr/trim/etc/version` mtime = 09-29 13:15) |
| 平台 | x86_64 自组装机(Intel Z370 + 核显) |
| 测试窗口 | 2026-10-08 22:52 ~ 10-09 23:45 |
| 安装方式覆盖 | 应用中心 UI 手动安装、appcenter-cli install-fpk(1.0.2) |
| 验证手段 | `sudo -u postgres psql -d trim_sac`(只读查询)+ `journalctl -u trim_http_cgi` |

## 三、期望行为 vs 实际行为

**期望**(按官方文档《统一网关》:入口配置声明 gatewayPrefix + gatewaySocket 后,
"该配置会注册 /app/myapp",请求转发到 target 目录下声明的 socket):

安装后 entry 表该应用行的 gateway_prefix / gateway_socket 非空;trim_http_cgi 扫描时
输出 `upstream register [/app/{prefix}] ... success`;`/app/{prefix}` 经登录校验后转发
至应用 socket。

**实际**:entry 表两列**为空**(url/title/icon 等其余字段正常导入);trim_http_cgi 从不
注册该上游;`/app/{prefix}` 一切请求(含已登录会话)404。

## 四、复现步骤

1. 构建最小 .fpk:`ui/config` 如下(manifest 具备常规字段,micro_app=true 与否不影响,
   见第五节变量隔离):

```json
{
  ".url": {
    "com.test.gatewayprobe.main": {
      "title": "GW", "icon": "images/icon_{0}.png", "type": "iframe",
      "protocol": "", "gatewayPrefix": "/app/gwprobe-test",
      "gatewaySocket": "gwprobe.sock", "url": "/app/gwprobe-test",
      "allUsers": true
    }
  }
}
```

   应用服务监听 target 目录下 gwprobe.sock(与本节声明一致)。
2. 应用中心 UI 手动安装(或 appcenter-cli install-fpk,两者结果相同)。
3. 查询注册表:

```sql
SELECT service_name, gateway_prefix, gateway_socket, url
FROM entry WHERE app_name = 'com.test.gatewayprobe';
```

   实际结果(gateway 两列为空,url 正常导入——证明导入器读取了同一份 ui/config):

```
 service_name | gateway_prefix | gateway_socket | url
--------------+----------------+----------------+----------------------------------
 ...main      |                |                | {"path":"/app/gwprobe-test"}
```

4. `journalctl -u trim_http_cgi` 中该应用**从无** `upstream register` 记录(对照:同批
   预装应用每轮扫描均有)。
5. 已登录浏览器访问 `/app/gwprobe-test` → 404;直接连应用 socket 同路径 → 200。

## 五、证据与变量隔离

测试矩阵(2026-10-09,同一台设备、同一导入器,**六次安装全部复现**):

| # | 安装方式 | gateway 声明形态 | micro_app | 前缀 | 导入结果 |
|---|---|---|---|---|---|
| 1 | CLI install-fpk | 纯网关(url=/app/前缀) | false | 含点 | 丢弃 |
| 2 | CLI install-fpk | 纯网关(升级) | false | 含点 | 丢弃 |
| 3 | CLI install-fpk | 混合(url=CGI+网关字段) | false | 含点 | 丢弃 |
| 4 | CLI install-fpk | 双入口(纯网关+混合) | false | **无点** | 丢弃 |
| 5 | CLI install-fpk | 双入口(同上) | **true** | **无点** | 丢弃 |
| 6 | **UI 手动安装** | 双入口(同上) | true | 无点 | 丢弃 |

已排除的变量:**micro_app 开关、前缀含点与否、混合声明、升级 vs 全新安装、UI vs CLI、
包结构(官方 fnpack 产物与手工等价 tar 的成员列表完全一致,另对照了商店应用 moo 的
.fpk,结构与我们的完全相同)**。

对照组(同一设备、同一导入器,entry 表中 gateway 字段非空的全部 13 条):

| 来源 | 应用(id 范围) | 示例 |
|---|---|---|
| 09-29 系统初始化批量导入(12 条,id 64184-64213) | 预装/初始化时恢复的应用 | miyin(/app/miyin/)、file.dedupe、fn-finstat、fndesk |
| 商店安装(1 条,id 90356) | moo(0.6.314) | /app/moo |

即:**导入器在"系统初始化批量导入"与"商店安装"两条路径上会导入 gateway 字段,在
"本地 .fpk 安装"路径上一律不导入。** 前缀含点的 /app/file.dedupe(app_name 含点)能
导入,说明并非前缀字符校验问题。

## 六、附带行为观察(同一机制,供参考)

1. **入口注册仅在首次安装导入,升级不重新导入**:应用升级(整体替换包文件)后
   entry 行不变(id 不变);运行期修改 ui/config 亦不影响注册表与桌面入口 URL——
   入口声明实际是"安装时快照"。若此为设计意图,建议文档明示;若否,与上一并修复。
2. trim_http_cgi 每 30 分钟(:25/:55)按 entry 表**全量重扫并清退出表外的上游行**——
   直接对 entry 表手工补写gateway 字段(模拟正确导入结果)后,下轮扫描即正常注册,
   证明 **entry 表是唯一闸门**,问题定位在安装期的字段导入,而非 trim_http_cgi 转发层。

## 七、影响面

- 本地开发与手动分发的第三方应用**完全无法使用统一网关**(WebSocket、常驻长连接、
  官方文档推荐的路由形态全部不可用),开发者按文档实现后功能静默失效,无任何报错。
- 规避手段只有回退 cgi 反代(index.cgi → TCP 回环),牺牲 WebSocket 与官方推荐架构。

## 八、期望的修复

1. 本地 .fpk 安装(UI 与 CLI)的入口导入,从 ui/config 完整导入 gatewayPrefix /
   gatewaySocket 字段;
2. (建议)提供入口重导入机制:安装/升级/应用启动时,或 trim_sac 暴露注册 API,
   使运行期声明的变更可生效。

## 九、附录:最小复现包

- 复现应用:网关存活探针(独立包,AF_UNIX 微服务 + 上述 ui/config,含构建脚本),
  构建产物 gatewayprobe-0.0.5.fpk(约 12 KB)可直接在任何 1.2.0701 设备复现第四节。
- 需要完整构建脚本、entry 表全量导出或真机远程排查配合,请随时联系。
