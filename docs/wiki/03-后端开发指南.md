# 03 后端开发指南

## 环境搭建

- Python 3.12+（本机开发用系统 Python；FPK 打包机交叉安装依赖见 [05 打包与部署](05-打包与部署.md)）
- 无需预装数据库——SQLite 单文件，默认落 `backend/data/nasdeck.db`
- 依赖安装：`pip install -e .`（或按 `pyproject.toml` 手动安装 fastapi/uvicorn/sqlalchemy/aiosqlite/apscheduler/psutil）

**Windows 本机坑（实测）**：pyenv 垫片对 `pip install` 不可靠（报「系统找不到指定的文件」），装依赖、跑测试一律用**真实解释器路径**，如 `C:/Users/WWTAW/.pyenv/pyenv-win/versions/3.13.13/python.exe -m pip install --user ...`。

## 启动与调试

```bash
cd backend
NASDECK_PORT=8766 python main.py          # 默认 127.0.0.1:8766（FPK 形态为 9800）
# Swagger: http://127.0.0.1:8766/docs
```

常用环境变量（全部 `NASDECK_` 前缀，见 `app/core/config.py`）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `NASDECK_PORT` / `NASDECK_HOST` | 8766 / 127.0.0.1 | 监听地址；**绑非回环前必须显式配置鉴权** |
| `NASDECK_DB_URL` | `backend/data/nasdeck.db` | SQLite 连接串（绝对路径须四斜杠） |
| `NASDECK_API_KEY` | 空 | api_key 鉴权形态 |
| `NASDECK_TRIM_AUTH` | false | 飞牛 CGI 反代形态（读=登录用户，写=管理员） |
| `NASDECK_PROXY_TOKEN` | 空 | index.cgi→后端共享密钥（FPK 安装期生成） |
| `NASDECK_RAW_KEEP_MINUTES` | 120 | raw 粒度保留分钟数 |
| `NASDECK_LOG_LEVEL` | dev 包 DEBUG / 正式 INFO | 日志级别 |
| `NASDECK_STATIC_DIR` | 空 | 指向前端 dist 时由后端托管 SPA |

非 Linux 平台（如 Windows 开发机）硬件采集自动降级：`/proc`、sysfs、smartctl 缺失的路径按「无数据」返回，接口不报错——**在 Windows 上调接口/跑测试是支持的工作方式**。

## 测试

```bash
cd backend                      # pytest/ruff 必须在 backend/ 目录跑
python -m pytest tests/ -q      # 139 用例，~5s，独立测试库（tests/_test_nasdeck.db 自动清理）
python -m ruff check app tests
```

- 测试库隔离：`conftest.py` 在导入 app 前设 `NASDECK_DB_URL`，会话级 `client` 夹具完成 `init_db`
- 硬件采集类测试用 monkeypatch mock glob/`run_cmd`，不依赖真实硬件
- 涉及 SQLite 服务内缓存的测试文件（如 `test_storage_topology.py`）用 autouse 夹具前后重置，防止同进程污染——**给带进程内缓存的模块写测试时照此办理**

## 编码约定

1. **零裸 SQL**：业务/DDL 一律 SQLAlchemy ORM / 检查器 / Index DDL 元素表达；连接 PRAGMA 只允许在 `db/session.py`（唯一豁免点，驱动层配置）。
2. **写入路径二选一**：周期采集纯插入 → `ingest.submit`（宁丢不堵）；API 需回 id 的 CRUD 与含读改写的事务 → 常规 session。
3. **缓存 miss 必回写**：API 路径里 TTL 缓存 miss 后重算的数据要 `set` 回缓存，防并发重复计算（参考 `api/v1/monitor.py` 各端点）。
4. **能力降级显式化**：工具缺失/非 Linux/读取失败 → 返回 `None`/空/`unknown`，让前端显式展示 `—`；不抛裸异常、不返回编造值。
5. **注释写"为什么"**：本仓库注释密度较高，凡真机踩坑（时区、fnpack、WAL、util-linux 2.38 等）都在现场注释里写明约束与日期——改动相关代码前先读注释，改完维护注释。
6. **日志**：外部工具每次调用的命令行/退出码/耗时在 DEBUG 级记录（`async_cmd._log_call`）——这是真机排障主线索，新工具调用别绕过它。

## 启动链（lifespan 顺序）

`main.py` lifespan：`init_db`（建表/自愈/索引收敛）→ `purge_legacy_aggregates`（一次性清 v1 失真聚合，幂等）→ `ingest.start()`（单写者 worker，先于调度器就绪）→ `scheduler.start()`（注册 1s/5s/60s/降采样后启动）→ `reconcile_on_startup`（遗留 firing 告警对账）/ `fcs_safe_takeover.load_state`（风扇接管状态对账）/ `restore_all_zones`（关停时恢复）在启停两侧对应。
