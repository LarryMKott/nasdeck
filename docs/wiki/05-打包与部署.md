# 05 打包与部署

## 一键打包

```bash
# Windows 开发机 / Git Bash（在仓库根目录执行）
C:/Users/WWTAW/.pyenv/pyenv-win/versions/3.13.13/python.exe scripts/build_fpk.py \
    --python C:/Users/WWTAW/.pyenv/pyenv-win/versions/3.13.13/python.exe
# 产物：build/fpk/nasdeck-fnpack-<version>.fpk（全流程约 2 分钟）
```

**`--python` 必传**：脚本默认指向 `backend/.venv`（本机不存在）；pyenv 垫片对子进程 pip 不可靠，须给真实解释器路径。

常用选项：`--skip-frontend`（复用 dist，须为 `--mode fpk` 产物）· `--builder manual`（纯 tarfile，真机验证过的老格式，Windows 下最稳）· `--skip-fnpack-download`。

### 流水线步骤

1. **前端**：`pnpm build --mode fpk`（base= cgi 反代前缀）
2. **图标**：仓库 `ICON_256.PNG` 生成 64/256 双尺寸与 `ui/images`
3. **staging 组装**：后端代码 + 随包 `storcli64` ELF + `fpk/` 布局
4. **依赖交叉安装**：10 个运行依赖以 `pip --platform manylinux2014_x86_64 --only-binary=:all: --python-version 3.12` 装进随包 `site-packages`——**装机不联网、不污染系统 Python**，解释器来自应用中心 `python312` 运行时（manifest `install_dep_apps=python312`）
5. **打包器**：官方 fnpack 1.2.3（自动下载至 `build/fpk/tools`，已存在则复用）优先；fnpack 产物在 Windows 有可执行位丢失的坑，脚本检测到即**回退手工 tarfile**（显式置 0755）——两个 `.fpk` 并存时**以 `nasdeck-fnpack-<version>.fpk` 为准装机**
6. **自检**：manifest 字段 / config JSON / 图标尺寸 / 目录结构 / 随包内容（site-packages、dist）

### fnpack 已知坑

- **校验失败退出码仍为 0**，只打印 `Packing failed`——脚本化判断必须查输出关键字 + 产物是否生成
- 打包前脚本会清理旧产物防误用；构建前确保 shell CWD 不在 `build/fpk/pkg` 内（rmtree 报目录占用）

## 版本单源

| 位置 | 角色 |
|---|---|
| `backend/pyproject.toml` | **唯一来源**，`config.py` 运行时读取 |
| `fpk/manifest` | `@VERSION@` 占位符，打包脚本注入，禁止手写 |
| `fpk/manifest` changelog | 升级弹窗文案，随版本手动维护 |
| `frontend mock.js about` | 演示值，不追号 |

版本号约定：`dev-x.y.z` 开发版（日志 DEBUG 便于真机排查）· `x.y.z` 正式版（INFO）。

## FPK 包结构（fnpack 标准布局）

```
fpk/（开发目录）                    安装后（/var/apps/com.dashboard.nasdeck）
├── manifest                       ├── manifest
├── cmd/                           ├── cmd/            # main + install/upgrade/uninstall×(init|callback) + config×2
│   ├── main                       ├── app.py → target 软链（健康检）
│   ├── install_callback           ├── server/         # app/ 目录内容：代码 + site-packages + dist + bin
│   └── ...                        ├── ui/             # 桌面入口（iframe → index.cgi 反代）
├── app/（→ target）               ├── var → @appdata  # DB、日志、端口文件、runtime.env（升级保留）
│   ├── app.py                     ├── etc → @appconf
│   ├── index.cgi（本机反代）        └── home → @apphome
│   └── ui/{config,images}
├── config/{privilege,resource}
└── wizard/install                 # wizard_port（默认 9800）
```

### 生命周期脚本要点（cmd/）

- `cmd/main`：start/stop/status（退出码 **0=运行中，3=未运行**）；解释器加 `PATH=/var/apps/python312/target/bin`；端口从 `${TRIM_PKGVAR}/port` 读取（白名单校验，非法回退 9800）；PID/日志落 `TRIM_PKGVAR`
- `install_callback`：端口占用预检；安装系统工具（smartmontools、lm-sensors、mdadm、dmidecode、i2c-tools、ethtool，核显机型加 intel-gpu-tools；无外网跳过并降级）；生成 `NASDECK_PROXY_TOKEN` 落盘
- `config_callback`：配置向导值经**白名单/数字校验**后写 `${TRIM_PKGVAR}/runtime.env`（如日志级别）——用户输入不裸拼
- 错误写 `${TRIM_TEMP_LOGFILE}` 后 `exit 1`，不 echo 到 stdout
- 脚本须可重复执行（安装/升级/配置都可能重跑）

## 真机安装与升级

```bash
# 设备端（fnOS）
appcenter-cli install-fpk nasdeck-fnpack-dev-x.y.z.fpk
appcenter-cli list / start / stop com.dashboard.nasdeck
```

或应用中心 → 手动安装 → 选择 .fpk（仅限本地测试）。升级走 `upgrade_init/upgrade_callback`：`var`（DB 与配置）随 `@appdata` 保留；DB 结构变更由启动时 `init_db` 自愈（白名单内整库重建，开发期数据可弃——正式部署前须替换为 Alembic）。

**发版前检查**：在计划支持的每个 fnOS 版本与架构实测安装/打开/主流程/权限边界；校验版本三处一致（pyproject / manifest 注入 / 关于页显示）。
