# 06 接口与数据模型

> 接口的字段级权威定义在 [前后端数据接口约定](../前后端数据接口约定.md)（下称"契约"）。本页是导航级摘要 + 数据库设计；**改接口必须同步契约**。

## 响应信封与错误码（契约 §1.2）

所有 JSON 接口统一信封：`{ code, message, data, timestamp }`；`code=0` 成功。业务错误由 `NasdeckError` 体系抛出：

| code | 异常 | HTTP | 场景示例 |
|---|---|---|---|
| 1001 | NotFoundError | 404 | 别名序列号不存在 |
| 1002 | InvalidParamsError | 400 | 参数非法 |
| 1003 | ExternalToolError | 500 | smartctl/storcli 缺失或超时 |
| 1004 | PermissionDeniedError | 403 | kill 进程命中保护名单 |
| 1005 | StateConflictError | 409 | 同盘已有进行中自检 |
| 2000 | — | 422 | 请求校验失败 |
| 5000 | — | 500 | 未处理内部错误 |

## 端点分组（均挂 `ApiKeyDep + TrimAuthDep`，WS 单独握手鉴权）

| 前缀 | 覆盖 |
|---|---|
| `/api/v1/monitor` | realtime / temperatures / summary / history（+stats/export） |
| `/api/v1/storage` | disks（含 partitions/health/temp）/ disks/{dev}/smart / disks/{serial}/alias / raid / volumes / self-tests |
| `/api/v1/system` | info / env / docker/containers / ports(+alias) / processes(+kill+whitelist) / settings |
| `/api/v1/control` | fans（zones/curves CRUD）/ curve/preview / fcs（安全接管 status/takeover/release） |
| `/api/v1/alert` | rules / events / channels（CRUD + test） |
| `/api/v1/report` | 健康报告生成 / 列表 / 下载 / 诊断包 |
| `/api/v1/hardware` | 硬件清单（主板/CPU/内存/网卡/阵列卡，slow tick 采集） |
| `/api/v1/ws/realtime` | WebSocket：realtime 1s / fans 5s / alert 事件增量 / pong |

写操作（非 GET）在 trim 形态下额外要求 `X-Trim-Isadmin=true`（管理员铁律，后端最终校验）。

## 数据库（SQLite 单文件，WAL 模式）

连接调优集中在 `db/session.py`（全仓唯一 PRAGMA 豁免点）：`journal_mode=WAL`（真机跳秒修复：默认 journal 下 1s 采集每 commit 全量 fsync，撞上 5s 写事务即被调度器跳秒）、`synchronous=NORMAL`、`busy_timeout=3000`。

### metric_points —— 历史指标（唯一大表）

- 三粒度同表：`granularity` ∈ `raw`(1s) / `1m` / `10m`，唯一约束 `(ts, granularity)`（ingest `ON CONFLICT DO NOTHING` 幂等）
- 索引：`(granularity, ts)` 复合索引服务全部热点查询；历史单列索引由 `init_db` 启动时幂等收敛
- **保留期**（`downsample_tick` 每 5min）：raw 默认 120 分钟（`NASDECK_RAW_KEEP_MINUTES`）→ 1m 30 天 → 10m 90 天，过期 DELETE；库规模恒定在几 MB
- 聚合口径：cpu/mem/net/disk 取均值，temp/gpu 取最大；桶键一律 UTC 墙钟串（`calendar.timegm`，不用 naive `.timestamp()`——非 UTC 机器会整体漂移）
- 查询口径：`query_history` 按窗口选粒度（≤raw 保留期查 raw；≤7 天 1m；更长 10m），超保留期窗口新旧两段拼接（聚合表滞后聚合，单查会漏最近几小时）；SQLite 端分桶降采样，单次 ≤500 点
- 写入：仅经 ingest 单写者通道（攒批 50 条/2s `executemany`）；温度随 fast_tick 从缓存内嵌进每行

### 其余表

| 表 | 用途 | 增长控制 |
|---|---|---|
| `alert_rules` / `alert_events` / `alert_channels` | 告警规则 / 事件（含通知轨迹）/ 通知渠道（config 脱敏存储） | events 查询限 500 |
| `fan_zones` / `fan_curves` | 风扇接管状态与曲线 | 用户数据量级 |
| `hardware_items` | 硬件清单快照（slow tick 每分钟 6 kind/轮） | 20 分钟剪枝，恒定 ~120 行 |
| `disk_aliases` / `port_aliases` | 用户自定义别名（按 serial / port） | 用户数据量级 |
| `kill_whitelist` | 进程终止保护名单（命中即 1004） | 用户数据量级 |
| `system_settings` | 键值设置（含降采样迁移标记等内部键） | — |

### 结构演进

无 Alembic 阶段：启动时 `init_db` 用 SQLAlchemy 检查器对照 `_REQUIRED_COLUMNS` 识别旧结构 → 白名单内整库重建（开发期数据可弃）；同时幂等收敛 metric_points 索引。**给模型加列后必须：更新 `_REQUIRED_COLUMNS` + 写旧库升级路径测试**（参考 `tests/test_db_schema.py`）；正式部署前替换为 Alembic 迁移。

## 数据流示例：一个温度读数的旅程

```
medium_tick(5s) → hwmon/sysfs 直读 + SMART 盘扫(60s 缓存) → temperatures 列表
  → realtime_cache['temperatures'] (TTL 15s) → WS/温度页/summary/fast_tick 内嵌落库
  → metric_points.temp_max (随 raw 行) → downsampler 1m/10m max 聚合 → 历史曲线
  → 告警引擎 ctx.temp_max（medium_tick 同事务评估）→ firing 事件 → 后台通知渠道
```
