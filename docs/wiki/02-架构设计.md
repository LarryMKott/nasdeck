# 02 架构设计

## 请求链路（为什么是 cgi 反代）

```
飞牛桌面图标（app/ui/config, iframe）
  → /cgi/ThirdParty/com.dashboard.nasdeck/index.cgi/   ← 飞牛网关校验登录态
    → index.cgi 本机反代 → http://127.0.0.1:9800       ← FastAPI (uvicorn)
```

- **不走统一网关（Unix Socket）**：飞牛会周期性清空第三方 gateway 入口导致 404（真机实测教训），改 cgi 反代后稳定。
- 端口仅绑 **127.0.0.1 回环**，不对外暴露；面板端口默认 9800，安装向导 `wizard_port` 可自定义，落盘 `${TRIM_PKGVAR}/port`（`index.cgi` 与 `cmd/main` 同源读取）。
- manifest 按 CGI 规范**省略 `service_port`** 并设 `checkport=false`，端口占用由 `install_callback` 预检（避免固定声明与用户自定义端口冲突）。
- `fpk/app/app.py` 是应用根目录的启动 shim：应用中心经 `/app/app.py` 软链做健康检（`cmd/main start` 时重建软链），并等价于 `python server/main.py` 的直接启动入口。
- SPA 静态资源由后端托管（`static_dir` 指向随包 `dist`），前端 vite 以 `--mode fpk` 构建时 base 指向 cgi 反代前缀。

## 鉴权模型（分级）

依赖注入层统一强制（`api/deps.py`），三种形态按配置自动判定：

| 形态 | 触发条件 | 读操作 | 写操作（非 GET） |
|---|---|---|---|
| trim（FPK 部署） | `NASDECK_TRIM_AUTH=true` | 须 `index.cgi` 转发的 `X-Trim-Userid` 头 | 还须 `X-Trim-Isadmin=true` |
| api_key | 设置 `NASDECK_API_KEY` | `X-API-Key` 头或 `?api_key=` | 同左 + 管理员语义由前端控制 |
| 无鉴权（本机开发） | 两者皆空 | 放行 | 放行 |

- **代理共享密钥** `NASDECK_PROXY_TOKEN`：`index.cgi → 后端` 的本机转发凭据，安装期生成落盘 `var/`。防的是网关剥离客户端自带 `X-Trim-*` 头后的伪造——身份头只能由持密 index.cgi 注入。
- WS 握手与 REST 同级鉴权（trim 头 / api_key / 回环放行 + Origin-Host 同源校验）。
- 前端 `info` 接口暴露 `is_admin`，写操作 UI 按 `identity.canWrite` 渲染；后端仍有最终校验（前端隐藏 ≠ 放行）。

## 采集调度（三级 tick + 降采样）

APScheduler（`tasks/scheduler.py`，`max_instances=1` + `coalesce`，采集过慢时顺延不并发）：

| 任务 | 周期 | 职责 |
|---|---|---|
| `fast_tick` | 1s | `/proc/stat`、`/proc/meminfo`、cpufreq **内核文件直读零 fork**；快照进实时缓存 + 指标行投递 ingest 通道（温度/GPU 从缓存并入，不重复采集） |
| `medium_tick` | 5s | 温度采集（hwmon 直读 + SMART 60s 盘扫缓存）→ 缓存；风扇调速输出 + 告警引擎评估（同事务一次 commit）；GPU 采样 |
| `slow_tick` | 60s | SMART 盘扫（健康/温度双产出）、阵列卡 storcli、硬件清单快照；维护 `disk_health`/`raid_degraded` 等缓存键 |
| `downsample_tick` | 5min | raw → 1m → 10m 聚合 + 保留期清理（详见 [06 接口与数据模型](06-接口与数据模型.md)） |

**设计要点：采集宁丢不堵。** 周期采集的纯插入数据一律经 **单写者 ingest 通道**（`db/ingest.py`）：内存队列（上限 600 行）串行化写竞争，攒批 50 条或 2s 先到为准 `executemany` 落盘；队列满丢新数据并限频记日志。任何新的周期采集点都不得在 tick 内直接开事务写库——含读改写的事务（温度回填历史上有、现为告警评估）才走常规 session 路径。

## 缓存体系（进程内 TTLCache，`services/monitor/cache.py`）

| 键 | TTL | 生产者 | 消费者 |
|---|---|---|---|
| `realtime` | 5s | fast_tick / API miss 回填 | WS 推送、`/monitor/realtime`、`/monitor/summary` |
| `temperatures` | 15s | medium_tick / API miss 回填 | fast_tick 落库内嵌、summary、前端温度页轮询 |
| `gpu` | 10s | medium_tick | fast_tick、realtime 快照 |
| `fan_outputs` | 10s | medium_tick | WS fans 事件 |
| `latest_alert_events` | 10s | medium_tick | WS alert 事件 |
| `disk_health` / `disk_failed` / `raid_degraded` | 120s | slow_tick | summary、告警上下文 |
| SMART 盘扫（服务内） | 60s | temperature 服务 | 盘温与健康共用一轮（零额外 fork） |
| storcli 采集 | 15s | storcli 服务（带锁） | raid API 与硬件采集共享 |
| lsblk 盘清单 | 60s | volumes 服务 | disks/summary/报告多端点共享 |

原则：**昂贵数据（fork 外部命令、全盘扫描）必须有 TTL 缓存且多消费方共享同一轮**；缓存 miss 的 API 路径要回写缓存（防止并发重复计算）。

## 实时推送（WebSocket + 降级轮询）

- 端点 `/api/v1/ws/realtime`：`realtime`（1s）/ `fans`（5s）/ `alert` 事件（增量去重）/ ping-pong 保活（20s）。
- 同一秒的快照全连接**共享一次 JSON 序列化**（`_snapshot_text`），N 客户端不放大 CPU。
- 前端经 Pinia store（引用计数）全站单连接；WS 断开指数退避重连，失败切 2s HTTP 轮询，恢复自动切回；**cgi 反代形态识别后直接轮询**（网关不透传 WS 升级，省掉必败重连空窗）。
- 页面全部 keep-alive，轮询定时器随 `activated/deactivated` 严格启停——切走页面不打接口。

## 告警与通知解耦

`medium_tick` 的事务里完成规则评估与事件落库（一次 commit 一次 fsync）；**通知发送在事务提交后**经 `schedule_drain()` 交给后台 task——慢渠道（邮件/Telegram）不占住 SQLite 写锁与 5s 调度。

## 历史数据流（写入 → 聚合 → 查询）

```
fast_tick(1s) → ingest 队列 → 攒批 executemany → metric_points(granularity='raw')
downsample_tick(5min) → raw→1m 聚合（SQL 端 avg/max）→ 1m→10m → 保留期 DELETE
查询 → query_history 按窗口选粒度（raw 保留期内查 raw，7 天内 1m，更长 10m；
        超保留期的窗口新旧两段拼接，降采样在 SQLite 端分桶完成，单次 ≤500 点）
```

详见 [06 接口与数据模型](06-接口与数据模型.md)。

## 关键设计决策索引（改代码前先读对应实现注释）

| 决策 | 位置 | 一句话理由 |
|---|---|---|
| cgi 反代而非统一网关 | `fpk/cmd/main` 头注释 | 飞牛清空第三方 gateway 入口（真机教训） |
| sqlite URL 四斜杠 | `fpk/app/app.py` | 三斜杠是相对路径，`TRIM_PKGVAR` 拼接须凑满四斜杠 |
| 零裸 SQL | `app/db/init_db.py` | 检查器/metadata 表达；PRAGMA 仅 `db/session.py` 豁免 |
| 启动结构自愈 | `app/db/init_db.py` | 无 Alembic 阶段的开发期兜底，白名单内整库重建 |
| WS 不用 `<transition>` | `UnraidLayout.vue` | 过渡依赖 rAF，后台节流环境会卡在 enter-from |
| 温度随 fast_tick 内嵌落库 | `tasks/collectors/fast_1s.py` | 替代逐 5s UPDATE 回填：写入减半、每行都有温度 |
