## R. 2.5D 立体机箱（机型自适应生成）⭐ 花哨 5 / 实用 4 / 工作量 L（拆三阶段交付）

**效果**：温度页视图切换扩展出「立体机箱」——一台等距视角的侧透机箱，**按这台机器的真实硬件自动长出来**：
2 盘 NUC 是紧凑单列盘位，4 盘塔式有硬盘笼和前后风扇，插了显卡就多一张卡，跑在 PVE 里则干脆不画机箱、
改为逻辑视图。部件全部由真实传感器驱动：

| 部件 | 数据源（全部现成，除注明） | 视觉编码 |
|---|---|---|
| CPU 散热器顶盖 | 温度服务 cpu 分区（60/75/85 分级沿用） | 面色绿→橙→红，满载热浪微光 |
| 内存条 | 内存占用（realtime 快照）；根数按 detect 槽位信息，缺省示意 2 根 | 点亮根数/呼吸频率 ∝ 占用 |
| 硬盘笼每个盘位 | 盘温（60s 缓存）+ **每盘 IOPS（二期 I 采集，见依赖）** | 面板色按温度梯度，活动灯按 IOPS 闪烁 |
| 风扇 | fan_outputs 实际 RPM | 扇叶转速同步，喷出气流粒子 |
| 气流粒子 | RPM + 温度联合驱动 | 粒子沿风道从进风流到出风，密度/速度 ∝ RPM |
| 显卡（可选部件） | GPU 服务（温度/占用，三平台已通） | 侧灯颜色 + 小风扇转动；无 GPU 整件不渲染 |
| 电源悬浮牌 | RAPL 功耗（Intel；无 RAPL 显"—"） | 实时瓦数数字牌 |
| 网口 | 每网卡 rx/tx kbps（实时流），口数按 detect 网卡清单 | 按吞吐闪烁 |
| 机箱内环境光 | board 温度分区 | 内壁氛围色 |

**交互**：
- 悬停任意部件浮出实时读数 tooltip；点击跳对应页（CPU→系统资源、盘→硬盘、风扇→风扇页、GPU→总览）。
- 机位切换：正等测 / 高俯 / 侧俯三档预设机位平滑重投影过渡；指针移动带视差微倾（伪环绕）。
- 「分解视图」开关：部件沿各自法线炸开悬停半空，看内部结构；再收回来。
- 模板切换器：自动选择的机型不对就在下拉里换（塔式/机架/紧凑/逻辑视图）。

### 模型生成方案比选（2026-10-08 增补）

| 方案 | 生成方式 | 真实环绕 | 观感 | 旧平板风险 | 依赖 | 数据驱动布局 | 工作量 |
|---|---|---|---|---|---|---|---|
| **A. CSS 3D 手工拼装**（原草案） | 部件=手写 div 挤压盒（preserve-3d），坐标 JSON | ✓ 任意 | 中（光影全靠手涂渐变） | **高**：老 WebView 的 z 排序/嵌套 3D 坑多 | 零 | ✓ | M-L |
| **B. 等距 SVG 程序化生成** ⭐推荐 | 布局 JSON → 自研等距投影渲染器（纯函数 ~300 行）→ 输出 SVG 分组；粒子 canvas 叠加共享投影函数 | ✗（预设机位 + 视差补足） | **高**（三面三明度烘焙光影，插画级） | **低**：纯 2D 合成，无 3D 兼容问题 | 零 | ✓✓ 模型即数据 | M |
| C. three.js 真 3D | three 基本体或 Blender glTF | ✓✓ + 辉光后期 | 最高 | 高：老平板 WebGL 无保底（仍需 2D 兜底=做两遍） | +600KB 级，破「零依赖」约 | ✓ | L-XL |
| D. AI 生图 + 热区 | 生成插画 + 隐形热区 | ✗ | 静态最漂亮 | 低 | 零 | **✗ 无法按硬件清单动态增删部件** | S |

**结论**：选 **B**，且「模型即数据」正是机型自适应的前提——渲染器固定不变，**适配全部发生在生成层**：
`硬件清单(inventory) × 参数化模板(template) → 布局 JSON → 渲染器`。换一台机器只换输入，不换代码。
（C 留作远期 R4「高配模式」选项；A 的 preserve-3d 在 Kiosk 老 WebView 上是排不掉的雷。）

### 机型自适应生成（本期核心设计）

**三层管线**：
```
inventory（detect hardware_items + fan_outputs + 盘清单 + DMI 信息）
    × template（参数化模板函数：塔式 / 机架 / 紧凑 / 逻辑视图）
    → layout JSON（部件盒体 + 传感器绑定）
    → isochassis 渲染器（不变）
```

**参数化模板目录**：

| 模板 | 适用机型 | 参数化点 |
|---|---|---|
| tower 塔式侧透（默认） | 自组/成品塔式 NAS | 盘笼行数 = ⌈盘数/5⌉；风扇位 = fan_outputs 实数；GPU/网口/内存条按清单增删 |
| rack 机架式 | 1U/2U/4U 机箱 | 前置横排盘位（支持 8/12 盘多列）、后置长条电源、风扇横列 |
| compact 紧凑型 | NUC / ITX / 一体机 / 蜗牛星际 | 单列盘位、板载低矮散热块、无 GPU 位、电源外置块 |
| virtual 逻辑视图 | PVE / ESXi / KVM 等虚拟机 | 不画机箱：主板抽象块 + CPU/内存胶囊 + 盘/网卡图标列，纯数据面板风 |

**模板自动选择**：
- 读 `/sys/class/dmi/id/sys_vendor`（或 product_name）匹配 QEMU/VMware/Microsoft → **virtual 逻辑视图**（零 fork 文件读）。
- 其余默认 tower；用户可手动切换模板（见持久化），切错只影响观感不影响数据。

**传感器自动映射**（解决「传感器在主板上的位置每台机器都不一样」）：
- 名称启发式自动绑定：label 含 cpu/pkg/core → CPU 块；nvme → M.2 区；盘温按 device 序 → 盘位 1..N；
  fan_outputs 按序 → 风扇位；acpitz/board → 环境光。
- 绑不上的传感器：作为「游离传感器」小方块吸附在主板区，悬停可读数——有数据就不丢。
- 映射错了：R3 提供拖拽重映射（沿用一期 F 的拖拽交互），改完持久化。

**零配置保证**：以上全部自动，任何一台机器打开即是可用的布局；部件无数据自动隐去或灰显，不占位不造假。
**持久化**：手动选的模板 / 盘位重映射 / 布局微调属**机器级**配置（所有访问者与 Kiosk 共享），存
system_settings（仅管理员可写，权限铁律一致），并纳入现有配置备份导入导出；不配置则永远全自动。

### 实现要点（按方案 B 展开）

1. **生成层**：模板 = 纯函数 `(inventory, options) → layout JSON`；layout 含部件盒体与传感器绑定，
   渲染器逐盒投影出「顶 + 左 + 右」三面（同一色相三种明度 = 烘焙光影），细件（通风孔/LED/数字牌）
   按类型追加 SVG pattern 与分组。投影纯函数可单测；layout 生成器同样可单测（喂不同 inventory 快照断言部件数）。
2. **数据绑定**：LED、扇叶、数字牌是独立 SVG 分组，属性由 realtime 快照驱动；着色沿用 temperature
   服务既有分级；fill 走 CSS 变量，四套主题直连换装。
3. **气流粒子**：canvas 叠加层与 SVG 共享同一个 `project(x,y,z)`，粒子沿风道样条流动（逻辑视图模板无
   风道则此层自动关闭）；rAF 节流 + 页面隐藏即停 + `prefers-reduced-motion` 直关。
4. **口径与假数据边界**：造型允许示意（内存条根数缺省 2 根属造型），**数据只经颜色/动画/数字承载**；
   无源部件中性灰 + 悬停显"—"。
5. **与既有功能的关系**：一期 F 的 2D 热力图保留不替换（2D 管精确读数与布局编辑，3D 管演示与直觉，
   拖拽交互与传感器映射思路同源）；二期 I 的盘位数据口径直接复用为本机箱硬盘笼，不重复造。

**依赖声明**：唯一数据缺口是每盘 IOPS（`/proc/diskstats` 直读差分，零 fork）。该采集在二期 I 名下；
**若三期先于二期 I 动工，则把这份采集并入 R1 第一批做**，其余数据全部现成。

**改动面**：`isochassis/` 模块（投影函数 + SVG 渲染器 + 模板生成器，纯函数可单测）+ `UChassis3D.vue`
+ TempsView 视图切换 + Kiosk 温度屏挂载点 +（视依赖）diskstats 采集器 +（R3）system_settings 布局字段。

## 风险与约定

- 性能护栏：SVG 节点预算 <1500（12 盘机架模板重点压测）、粒子池同屏上限 200 + rAF 单实例；帧率 <30 自动关粒子层降级为 CSS 气流线。
- 无 WebGL 依赖，Kiosk 老平板无兼容保底问题（方案 B 的核心收益）。
- 布局是机器级配置：system_settings 仅管理员可写，与权限铁律一致；未配置永远全自动，不存在「必须先配置才能看」。
- 新文案走 `t()` 且 key 加引号（i18n 约定）；只读展示无权限面改动；新快照字段同步 Pydantic 与接口文档。
- R1/R2/R3 三段独立提交，R1 单独成立即可上线（一台会变色、长得对的机箱已经是完整花活）。
