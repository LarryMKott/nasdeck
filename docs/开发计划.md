## M1 · v0.2.0「看得见未来」——把历史库用起来

核心思想：SMART 和容量数据现在只看"当前值"，落历史后能**预测**。

### 1.1 SMART 趋势落库 + 变化速率告警 ✅（已实现，2026-10-05）

- **后端**：
  - 新表 `smart_points(ts, device, attr_id, value, raw)`，只存 1h/1d 两级粒度（SMART 变化慢，不进 metric_points）。〔落地为 `ts/granularity/device/metric/value/raw_text`，metric 用名称而非 id（ATA/NVMe 统一）〕
  - 新任务 `tasks/collectors/smart_15m.py`：15 分钟一轮，`smart.py:smart_report` 逐盘串行采集关键属性（Reallocated/Pending/Uncorrectable/Wear_Leveling/温度），scheduler 注册 job。
  - `alert/engine.py` 新增规则类型 `smart_rate`：按属性 7 天增量评估（如重映射扇区 7 天 +N），阈值由用户配置。
  - 新 API `GET /api/v1/storage/trend?device=&attr=&range=`（契约 §存储 增补）。
- **前端**：DisksView 盘详情加属性趋势 sparkline；告警规则编辑器加 `smart_rate` 类型。
- **验收**：某属性 7 天增量超阈值 → 触发告警；趋势图有真实点，无源盘显示"—"。

### 1.2 容量预测

- **后端**：
  - 新表 `volume_points(ts, mount, used_gb)`，slow_60s 或新 5m job 落点。
  - 预测服务：最近 14 天线性回归 → `days_to_full`；增速≈0 返回 null。
  - 告警规则类型 `capacity_forecast`：剩余天数阈值。
  - `GET /storage/volumes` 响应增补 `forecast` 字段（**注意 response_model 静默过滤，必须同步改 Pydantic model**）。
- **前端**：StorageView 每卷显示"按当前增速约 N 天写满"，无增速显"—"。
- **验收**：灌数据让 /tmp 增长 → 预测天数收敛合理。

### 1.3 SMART 定期巡检

- **后端**：`self_test.py` 已有在线自检能力，补调度：APScheduler cron 每周低峰时段逐盘串行 short test，结果写事件、异常走告警。设置项（开关+星期+时刻）持久化，仅管理员可改。
- **前端**：AutomationView 加巡检计划卡片（复用现有规则 UI 风格）。
- **验收**：真机触发 short test → 完成后事件可见、异常盘告警。

## M2 · v0.3.0「会动手」——自动化与容器

### 2.1 IF-THEN 剧本引擎

- **后端**：`alert/engine.py` 规则模型加 `actions[]`（notify=现有渠道广播 / fan_full=风扇接管拉满 / report=生成诊断报告 / event=仅记事件），条件评估沿用现有持续时长逻辑。动作执行失败记事件不中断。
- **前端**：AutomationView 规则编辑器从"单通知"升级为动作多选列表。
- **验收**："CPU>90% 持续 5min → 风扇全速 + Bark 推送"端到端成立。

### 2.2 容器资源监控

- **后端**：`system/docker.py` 加 `container_stats()`：cgroup v2 直读 `/sys/fs/cgroup/system.slice/docker-<id>.scope/`（memory.current、cpu.stat），零 fork；cgroup v1 路径回退检测，两者都不支持则该列返回 null。medium_5s 缓存。
  - API `GET /system/docker` 响应增补 stats 字段。
- **前端**：DockerView 列表加 CPU%/内存列 + 按资源排序。
- **验收**：真机与 `docker stats` 口径一致（±10%）。

### 2.3 容器退出告警

- **后端**：medium_5s 对比容器状态缓存，非手动 stop 的退出（Exited/OOM）→ 事件+告警。手动 stop（经 API 记录意图）不告警。
- **验收**：kill 掉容器 5s 内告警；正常 stop 静默。

### 2.4 RAID 同步/重建进度

- **后端**：`storage/raid.py` 补采集 `/proc/mdstat` 的 resync/rebuild 进度、速度、预计完成（storcli 阵列取对应字段）。进行中每分钟写事件进度。
- **前端**：StorageView 阵列卡片加进度条与预计完成时间。
- **验收**：真机 rebuild 期间进度实时可见（真机验证项）。

### 2.5 时段风扇计划（夜间静音）

- **后端**：`curve_engine.py` 支持时段规则：指定时间窗内套用偏移曲线（如 23:00–07:00 目标温度 +4°C）。设置持久化；失控保护优先级高于任何时段规则。
- **前端**：FanView 曲线编辑器加时段标签与启停。
- **验收**：跨时段切换生效，失控保护行为不受影响（pytest 覆盖边界时刻）。

## M3 · v0.4.0「省心」——运营与安全

### 3.1 周报/月报自动推送

- **后端**：`report.py` 出周报摘要（可用率、最高温、告警次数、容量变化、SMART 变化），scheduler cron 推送到所选渠道（email/telegram/bark/webhook 全现成）。支持"立即发送"调试按钮。
- **前端**：AutomationView 加报告推送设置。
- **验收**：真机手动发送 → 邮箱/TG 收到周报。

### 3.2 统一事件时间线

- **后端**：alert 的 events 表扩为通用事件（加 `source`：alert/fan/smart/docker/system），各服务统一写入；`GET /alert/events` 支持 source 过滤。
- **前端**：新"事件"页（时间线布局）：风扇接管、失控保护、自检完成、容器退出、端口异动、告警一屏回溯。
- **验收**：触发失控保护 → 时间线能看到完整因果链。

### 3.3 新增监听端口告警

- **后端**：slow_60s 对比端口快照，新监听且不在白名单 → 事件+告警（去重：同端口 24h 只报一次）。
- **验收**：起测试端口 60s 内告警；已设 alias 的端口不报。

### 3.4 系统日志哨兵

- **后端**：低频（5m）增量读 `journalctl -k`/dmesg，正则聚合 I/O error、ECC、温度、SMART 类关键行，命中 → 事件+告警，带去重窗口。
- **验收**：单元测试模拟日志注入；真机验证项。

### 3.5 配置备份/恢复

- **后端**：导出 settings+曲线+告警规则+渠道+端口别名为 JSON（渠道密钥默认脱敏排除，可选包含）；导入做 schema 校验+版本兼容。仅管理员。
- **前端**：SystemView 加导出/导入按钮。
- **验收**：导出→改乱→导入恢复；pytest 覆盖 schema 版本兼容。

### 3.6 Prometheus /metrics 端点

- **后端**：`/api/v1/metrics` 手拼 exposition 文本（CPU/mem/temp/net/disk/SMART/fan/gpu），直读实时缓存，不引入 prometheus_client 依赖。仅绑回环安全模型不变（由用户自行反代给 Prometheus）。
- **验收**：curl 抓取正常；wiki 给出 prometheus scrape 配置示例。

## 工程约定（每个特性通用）

1. **契约先行**：接口改动同步 `docs/前后端数据接口约定.md`；FastAPI `response_model` 会**静默过滤未声明字段**——新增响应字段必须同步改 Pydantic model。
2. **采集哲学**：新指标优先找 `/proc`、`/sys` 内核文件直读（零 fork）；外部命令采样间隔 ≥5s；SMART 这类重 fork 的放独立低频任务。
3. **数据库**：SQLite 已启 WAL；新表建表语句走 init_db 幂等收敛路径。
4. **前端分层**：endpoints（唯一持 URL+缓存）→ models（对齐 Pydantic）→ services（组装视图形状）；视图零 URL 字符串；nas 组件（u-icon 等）显式 import。
5. **权限与数据**：写操作仅管理员（后端强校验）；正常形态必须真实采集，无数据源显式"—"，mock 仅演示回退。
6. **质量**：pytest/ruff 在 `backend/` 下运行；每特性带测试，基线 139 项全绿；注意 lint-staged 会重排文件，提交前重查 git status（dev 上还有在途的风扇/告警改动需先收口提交，再动工本计划）。
7. **真机验证**：涉及 fork 外部命令、cgroup 路径、mdstat 进度的特性，列入真机验证清单（fnOS 192.168.31.240）。
