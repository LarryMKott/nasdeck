# nasdeck 花活提案四期——开源引入专项（design-only，待拍板）

> **状态（2026-10-09）**：新增提案，未实现。一期 A–H 已上线，二期 I–Q、三期 R 待拍板；本期 S–X 编号接续。
> 本期主题：在「可引入开源项目」增补（见二三期文档头部）的前提下，给出**带具体开源选型**的花活方案——
> 每项 = 花活功能 × 具体开源件（候选比选 / 体积 / 许可证 / 活跃度）× 改动面 × 退出策略。
> 老原则不变的部分：真实数据（无源显"—"）、`t()` 文案 key 加引号、写操作仅管理员、动画隐藏即停 + `prefers-reduced-motion`、每项独立提交可单独砍。

## 引入总则（比功能本身更重要，先立规矩）

1. **许可证红线**：仅收 MIT / Apache-2.0 / BSD 系；GPL/AGPL 一票否决——FPK 产物打包分发，不碰传染性义务。
2. **离线自托管**：fnOS 应用跑在内网，所有依赖 npm 安装打进产物，**禁止运行时 CDN / 外网回源**；不得含遥测、统计、字体外链。
3. **体积预算**：单件 gzip ≤ 60KB；一律 dynamic import 按视图懒加载，**首屏 bundle 不增一字节**；build 时对 chunks 体积做断言守门。
4. **兼容底线**：渲染技术 canvas2d / SVG / DOM 优先；WebGL 系必须能力探测 + 自动降级到既有 2D 方案（三期 R 的等距 SVG 渲染器就是现成兜底）。
5. **活跃度门槛**：近一年有 release 或持续 commit、issue 有响应；单人维护项目（如 uPlot）在 API 稳定 + BusFactor 可接受时放行。
6. **适配层隔离**：引入件一律封装在 `src/modules/nas/vendor/` 适配模块后面，视图不直接 import 库 API——库可替换、可砍；砍掉后走自研降级路径，功能主链路不破。
7. **引入粒度**：库 / 组件 / 字体级；**不引入整站级项目**（netdata / glances / portainer 类）——nasdeck 本身就是监控站，整站引入是换掉自己，不是花活。后端采集链路维持 stdlib + psutil（fork 敏感，Q 跑分已明确不引 fio/dd），开源引入集中在前端表现层。
8. **锁版本**：新依赖 pin 精确版本进 lockfile；升级走独立 chore 提交并过一遍真机 WebView 冒烟。

## S. 图表引擎 uPlot：示波器与历史曲线全面升级 ⭐ 花哨 3 / 实用 5 / 工作量 M

**引入件**：[uPlot](https://github.com/leeoniya/uPlot) —— MIT，约 48KB min / **13KB gzip**，1.6.x 持续维护（单人稳定核心），canvas 2d 渲染、老 WebView 无忧。

| 候选 | 体积（gzip） | 许可证 | 评注 |
|---|---|---|---|
| **uPlot ⭐** | ~13KB | MIT | 时序性能天花板（十万点毫秒级），十字线/框选缩放/图例开关原生内置 |
| ECharts | ~330KB | Apache-2.0 | 功能最全但体积 25 倍，雷达/热力等大半用不上（真要雷达图再单议） |
| Chart.js | ~70KB | MIT | 中庸之选，时序大数据性能明显弱于 uPlot |
| 自研维持 | 0 | — | USpark/ULineChart 已到收益边界：缩放、十字线、抽稀全是体力活 |

**效果**：
- 示波器双模式：现有自研 canvas 荧光滚动波形保留为「实时模式」（那是灵魂，不换）；历史模式换 uPlot 引擎——30 天数据**流式拖动、框选缩放、十字线读数、多通道图例开关**，一屏切换两种模式。
- 一套引擎铺开吃遍全站：USpark 迷你趋势、M 的容器 24h 趋势、Q 跑分实时曲线、J 预言 sparkline 全部走同一封装。
- uPlot 原生 LTTB 抽稀，90 天原始序列直接画，不再依赖预降采样。

**实现要点**：
- `vendor/uplot.js` 适配层：四套主题 CSS 变量 → uPlot 色板映射；`useUPlot()` 组合式封装（尺寸自适应、页面隐藏即 pause、数据环形缓冲对接）。
- dynamic import：进入示波器页或展开趋势卡才拉加载块。
- 迁移节奏：先迁示波器历史模式 + 历史趋势页两处验证，USpark 等小件渐进跟迁，不强制一次换血。

**改动面**：新依赖 1 件 + vendor 适配层 + OscilloscopeView 历史模式重接 + HistoryTrendView 换引擎（USpark/ULineChart 渐进可选）。

## T. 磁贴自由布局 grid-layout-plus：总览 / Kiosk 编辑模式 ⭐ 花哨 4 / 实用 5 / 工作量 M

**引入件**：[grid-layout-plus](https://github.com/qmhc/grid-layout-plus) —— MIT，vue-grid-layout 的 Vue 3 正统续作，`<script setup>` + TS 原生，约 40KB min / 12KB gzip 级，社区公认的 Vue 3 首选拖拽网格。

**效果**：总览页磁贴与 Kiosk 轮播卡支持「编辑布局」模式——拖拽换位、拉拽改大小、磁贴显隐排序；总览与 Kiosk 各一套布局 profile，存机器级配置（system_settings，管理员可写，权限铁律一致）。给客户摆一屏定制监控墙，是实打实的产品力。

**实现要点**：
- DashView 磁贴区包 `<GridLayout>`：磁贴组件本身不动，只包一层拖拽/缩放句柄；顶栏铅笔钮切换编辑态（编辑态仅管理员可见）。
- 布局序列化 JSON → system_settings 新字段（同步 Pydantic + 纳入配置备份导入导出）；非管理员只读应用布局，Kiosk 轮播分组吃同一份显隐/顺序。
- 降级路径：布局为空、解析失败或组件加载失败 → 回退现有写死网格，功能无损（适配层隔离原则的直接体现）。

**改动面**：新依赖 1 件 + DashView/KioskView 布局层 + system_settings 字段 + Pydantic。

## U. 立体机箱「高配模式」：TresJS（three.js）+ 能力探测兜底 ⭐ 花哨 5 / 实用 3 / 工作量 L（R 完成后的增量阶段）

**引入件**：[TresJS](https://tresjs.org)（MIT，Vue 3 声明式 three.js 渲染器，组织化活跃维护）+ [three](https://github.com/mrdoob/three.js)（MIT，约 600KB min / 170KB gzip 核心级）。

**效果**：三期 R 的方案比选里，three.js（方案 C）当时被「破零依赖」压到远期 R4。依赖已解禁，现在把它正式立项为 **R 的第四阶段「高配模式」**：真 3D 机箱、辉光后期（UnrealBloomPass 可选档）、自由环绕视角；**同一套 layout JSON 喂两个渲染器**——SVG 渲染器（三期 B，兜底/低配）与 three 渲染器（高配），数据绑定层、传感器映射、模板生成完全复用，R 的工作不被替换而是被继承。

**实现要点**：
- 首次进入探测：`WebGLRenderingContext` 可用性 + 首帧实测帧率（<30 判低配）→ 永久回退 SVG 模式并记 localStorage 不再折腾；手动「强制 2D」开关并存。
- 部件几何用 three 基本体程序化拼装（Box/Cylinder 足够），**不引 glTF 模型资产**，控制体积与素材管线；材质着色沿用温度分级 CSS 变量同源色值。
- dynamic import：three 全家仅在「立体机箱页 + 高配模式生效」时加载；Kiosk 老平板永远走 SVG 兜底。
- 代价直说：懒加载块 +170KB 级 gzip；三期 R1–R3 未完成前本项不动工（前置依赖）。

**改动面**：新依赖 2 件 + `isochassis/three-renderer` + UChassis 视图切换加「高配」档 + 探测模块。前置：三期 R 至少交付 R1/R2。

## V. 分享卡 2.0 与体检报告出图：SnapDOM ⭐ 花哨 3 / 实用 4 / 工作量 S

**引入件**：[@zumer/snapdom](https://github.com/zumerlab/snapdom) —— MIT，**约 5–6KB gzip，零依赖**，活跃维护；对比 html2canvas（40KB+ 级）小一个量级，SVG 序列化路线对文字/渐变/圆角/嵌入字体的保真度更高。

**效果**：
- 一期 B 分享卡从「Canvas 2D 手绘模板」升级为「DOM 模板直接出图」——用真组件 + 真主题排版，四套模板的排版自由度大增，改样式不再等于重写 canvas 绘制代码。
- 二期 N 一键体检的报告页整页截图出 PNG，**报告样式 = 屏幕样式**，零双份维护。
- 输出 PNG/JPG/WebP/Canvas 可选，文件名约定沿用 `nasdeck-status-<date>.png`。

**实现要点**：
- `vendor/snapdom.js` 适配层：`captureStatusCard(el)` / `captureReport(el)` 两个语义 API + 下载封装 + try/catch 回退旧 canvas 模板（旧模块保留不删，失败自动降级）。
- 卡内字体须随包自托管（本就如此，无新增动作）；出图分辨率设 2x 适配视网膜分享。

**改动面**：新依赖 1 件 + vendor 适配层 + DashView 分享卡按钮改路径 +（N 落地后）体检报告接同一 API。

## W. 氛围微花活包：canvas-confetti + countup.js + DSEG 数码管字体 ⭐ 花哨 4 / 实用 2 / 工作量 S

**引入件**（三小件合计 gzip ~10KB + 字体子集 ~40KB）：
- [canvas-confetti](https://github.com/catdad/canvas-confetti)（MIT，约 3–4KB gzip）
- [countup.js](https://github.com/inorganik/countUp.js)（MIT，约 3KB gzip）
- [DSEG 字体](https://www.keshikan.net/fonts-e.html)（SIL OFL 1.1，7 段/14 段数码管开源字体，woff2 子集化后单件 <10KB）

**效果**：
- 一键体检（N）总分揭晓瞬间：分数环描边完毕，礼花从环心喷出——仅 ≥90 分触发，`prefers-reduced-motion` 直关。
- Kiosk 时钟与 POST 开机动画（O）的内存计数用 **DSEG7 数码管字体**，机房监控墙瞬间「硬」起来；温度数字牌、跑分速度读数可选同款 14 段。
- Kiosk 大数字滚动、体检总分、跑分成绩统一 countup.js 缓动，替代各处手写 rAF 计数逻辑。

**实现要点**：confetti 挂全局一次性覆盖层，触发后即销毁；DSEG 只子集化实际字形（0-9 : . % °C 等），按需 font-face；`useCountUp()` 封装三处复用。

**改动面**：新依赖 3 小件 + KioskView / O 开机动画 / N 体检各自接入；零后端。

## X. 温度年历热力墙：cal-heatmap ⭐ 花哨 4 / 实用 3 / 工作量 S-M

**引入件**：[cal-heatmap 4.x](https://github.com/wa0x6e/cal-heatmap) —— MIT，作者本人生产在用的活跃项目，GitHub 贡献墙同款时间序列日历，DOM/SVG 输出、老 WebView 无忧，体积约 20KB 级。

**效果**：历史趋势页新增「年历」视图——365 天格子墙：每日最高温/平均温着色，颜色阶沿用温度分级；点击某天展开当天温度曲线（复用 S 的 uPlot）。配合二期 J 硬盘预言，每块盘可再加「坏日子日历」——SMART 属性恶化日高亮，把 smart_points 攒的 90 天历史变成一眼可读的岁月墙。纯展示零新增采集（历史库按天聚合查询一次）。

**实现要点**：
- 新增 1d 桶聚合端点（读现成历史库，纯 SQL 聚合）；无数据年份显空格不造假。
- 四套主题色阶走 CSS 变量；`range`/`domain` 用 day+month 两档；本项无动画，reduced-motion 天然无关。

**改动面**：新依赖 1 件 + 历史聚合端点 + HistoryTrendView 年历 tab +（可选）DisksView 盘级日历。

## 建议组合

- **性价比之王**：S uPlot + V SnapDOM——两件小依赖换全站图表交互与出图自由度，先做这两项验证引入总则跑得通
- **产品力担当**：T 磁贴自定义布局——演示定制大屏的杀招
- **门面担当**：U 三维高配（等 R 落地后）+ W 氛围包——「哇」时刻密度最大化
- **数据情怀**：X 年历热力墙——把 90 天历史库变成可以看的岁月

## 风险与约定

- bundle 守门：build 产物 chunks 体积断言进 CI/本地脚本——首屏字节数不增、懒加载块超预算即失败。
- 每项引入独立提交；`vendor/` 适配层内附一段「为何引入此件」注释——半年后回看知道为什么。
- S/X 有小后端面（聚合端点），其余纯前端；涉及新字段的同步 Pydantic 与接口文档（response_model 静默过滤前科，重点自查）。
- Kiosk 老平板是第一验收环境：每项落地后旧平板冒烟一遍（S/W/X 走 canvas2d/DOM 天然安全，T 需验证拖拽触屏，U 有探测兜底）。
- 触屏可用性：T 的拖拽在触屏上需 native touch 支持（grid-layout-plus 支持），Kiosk 只读态不显示句柄。
