# nasdeck 操作手册

> 本手册对应 **fnOS 版 0.1.0（正式版）**。nasdeck 是飞牛 OS 上的硬件监控面板：FastAPI 采集 + Vue 3 界面，以标准 FPK 应用装进飞牛桌面。面向开发者的架构与接口文档见 [项目 Wiki](wiki/Home.md)。

## 一、nasdeck 是什么

把原本要 SSH 敲命令才能看到的硬件状态，做成网页一眼看完：

- 你有什么硬件：CPU / 内存 / 主板 / 显卡 / 阵列卡 / 网卡 / 硬盘
- 硬盘健不健康、多少度、要不要换
- 风扇转多快，能不能让面板接管调速
- 存储：阵列 / 卷 / 拓扑关系
- Docker 容器、端口占用
- 温度超了会不会自动报警

一句话：**你 NAS 的「仪表盘 + 风扇遥控 + 报警器」三合一。**

## 二、安装与打开

1. 飞牛 **应用中心** 手动安装 `nasdeck-fnpack-x.y.z.fpk`（安装向导可自定义面板端口，默认 9800）。
2. 安装时自动安装系统工具（smartmontools / lm-sensors / mdadm / dmidecode / i2c-tools / ethtool，Intel 核显机型加装 intel-gpu-tools）——**无外网时跳过，对应功能自动降级**，不影响其余功能。
3. 桌面出现「NAS硬件监控」图标（对所有用户可见），点开即用；面板经飞牛 cgi 反代打开，**需登录飞牛账号**。
4. 面板端口只绑本机回环，**不要把端口直接暴露到公网**；外网访问走飞牛自带的远程访问 / 反向代理。

## 三、界面总览

顶栏共 **13 个页签**：总览 / 存储卷 / 硬盘 / 硬件检测 / 系统资源 / 温度 / 趋势 / Docker / 端口 / 风扇 / 自动化，外加操作手册与关于。右上角提供页签搜索、通知铃铛（活动告警数）、主题切换（黑 / 白 / 跟随系统）、用户菜单。

**左上角汉堡按钮**：切换页签样式——「完整样式（图标+文字）↔ 纯图标（启动器式方块）」，选择会记住，下次打开保持。

**窄窗口 / 手机**：页签样式随窗口宽度自动切换——宽窗口显示完整页签，中等宽度自动转纯图标（完整页签放不下时），窄窗口（约 1100px 以下，如飞牛桌面小窗、手机浏览器）页签条收起，点左上角按钮呼出**抽屉式菜单**：全部 13 项带图标分列，顶部带页签搜索，点击条目即跳转并收起，也可按 Esc 或点遮罩关闭。

- 所有页签切换零刷新，切回的页面立即显示上次内容并自动更新（keep-alive）。
- 切走的页面会停止轮询，不白白打接口。
- **权限**：普通用户可查看全部监控数据，设置类 / 写操作入口自动隐藏；风扇调速、进程释放、自检发起等**仅管理员可用**（后端同样强校验，前端隐藏不是唯一防线）。

## 四、各页面逐一讲解

### 4.1 总览 —— 打开即看的仪表盘

秒级自动刷新（WebSocket 推送，cgi 形态自动降级为 2 秒轮询）：

- **CPU**：总占用 + 逐核占用，实时频率。
- **内存**：用户视角占用（total − available）、buffers / cached / 保留 / swap 占用。
- **网络**：合并全部真实网口的上下行吞吐（自动剔除 veth / docker 桥等虚拟口，不重复计数）。
- **磁盘 IO**：整机读写速率。
- **GPU 监控**：利用率 / 温度 / 显存 / 频率（Intel 核显经 intel_gpu_top 长驻采样；无核显 / 独显时该卡显式降级）。
- **功耗**：CPU 封装实时功耗（Intel RAPL 硬件测量；无 RAPL 的平台显示 —）。
- **存储卷概览 / 硬盘温度 / 风扇转速 / Docker 容器 / 活动告警**：各一张摘要卡，点击标题可跳转对应页面细看。

页头显示「最后更新」时间；演示数据仅在后端不可达时整页出现（带「演示数据」角标），正常形态不会混入假数据。

### 4.2 硬件检测 —— 你有哪些硬件

按硬件分卡平铺：**系统信息**（主机名 / 系统 / 内核 / 运行时长）、**主板**（DMI 直读品牌 / 型号 / BIOS / 芯片组）、**处理器**（型号 / 核心 / 实时频率 / 占用）、**内存**（品牌取自 SPD 直读，区分模组厂与颗粒厂）、**网卡**（IP / MAC / 协商速率 / 驱动，只列真实物理口）、**阵列卡**（自动识别三种形态：MegaRAID 阵列卡 / HBA 直通卡 / 无卡纯 SATA，各有对应信息）、**磁盘概览**（每块盘型号 / 容量 / 接口 / 健康速览）。

页面底部是**运行环境自检**：安装期自举的工具（smartctl / sensors / mdadm / storcli 等）与风扇驱动加载状态实时呈现，缺失项带安装提示——「哪个功能为什么没数据」先看这里。

### 4.3 硬盘 SMART —— 健康体检

- 表格列出每块盘：型号 / 容量 / HDD·SSD / 温度 / 通电时长 / 健康 / 别名 / 操作。
- **健康**四级：正常（SMART 通过）/ 警告（重映射扇区等缺陷出现）/ 故障（SMART 判定失败）/ 未知（盘休眠或工具缺失）。
- **休眠盘**：`-n standby` 模式探测，休眠盘不打扰（该轮无温度读数，显示 —），不唤醒、不影响休眠。
- **别名**：管理员可给盘起好记的名字（按序列号持久化，重启不丢）。
- **在线自检**（管理员）：短自检 / 长自检 / 搬运性自检三种，后台运行、进度实时显示，完成后按 smartctl 自检日志给出 真实结论（完成 / 中止 / 报错）。同一块盘同时只允许一个自检。
- **周期巡检**（管理员，自动化页）：设置每周固定时间逐盘自动短自检（默认关闭），结果写入事件历史，异常盘向全部启用的通知渠道告警；自检会短暂唤醒休眠盘。
- **健康趋势**（硬盘页）：重映射扇区 / 待定扇区等关键指标按小时粒度画近 30 天趋势线；配合自动化页的「SMART 增速」告警规则（7 天增量超阈值即推送），盘要坏早几周知道。
- **写满预测**（存储卷页）：按最近 14 天增速估算每个卷「约 N 天写满」；刚接入不足 6 小时或增速≈0 时显示 —。
- 阵列卡背后的物理盘（系统无 /dev 节点）在检测页可见详情，但**不支持在线自检**。

### 4.4 存储卷 —— 阵列与拓扑

- **阵列卡信息卡**：MegaRAID 显示型号 / 驱动 / CacheVault 状态；HBA 直通显示说明。
- **阵列设备表**：每块盘的角色徽章（RAID 成员 / 热备 / 直连）、温度、容量、健康状态。
- **卷 / 数据卷卡**：挂载点容量与使用率。
- **存储拓扑树**（本页核心）：真实层级 **控制器 → 阵列 → 成员盘 → 分区 / 挂载点**——MegaRAID 显示每块物理盘的槽位（E:S）与热备标记；软阵列（md）显示成员分区；直连盘逐盘列出分区与挂载点。节点按健康着色，一眼看出「哪块盘在哪条链路上、出了问题影响谁」。
- 阵列操作卡（校验 Parity / 启停）当前版本为**管理员界面入口，执行链路尚未接入**——点击不会真的操作阵列，请继续用 storcli / 飞牛自带工具。

### 4.5 系统资源 —— 任务管理器风格

- 实时卡：**CPU 使用率**（逐核）/ **内存** / **RAPL 功耗** / **网络吞吐** / **磁盘 IO**。
- 下方 **24 小时折线图**：CPU / 内存占用率 / 网络吞吐 / 磁盘读速率，数据来自面板历史库。

### 4.6 温度监控 —— 温度墙

全机温度测点一面墙：主板各测点（英文代号自动转译）、CPU（★最准角标 = CPU 内部传感器）、NVMe 逐盘、机械盘 SMART 温度、芯片组。绿 = 正常 / 橙 = 偏高（≥60℃）/ 红 = 过热（≥75℃，临界 85℃）。每 5 秒刷新。

### 4.7 趋势 —— 历史与报告

- **六个维度**切换：CPU / 内存 / 温度 / 网络 / 磁盘 IO / GPU；**时间范围** 24 小时 / 7 天 / 30 天。
- 数据存本地 SQLite（重启不丢）：秒级原始点保留 2 小时 → 按分钟聚合保留 30 天 → 按 10 分钟聚合保留 90 天，库体积恒定不膨胀。
- **区间统计**：当前窗口的均值 / 峰值 / 采样点数。
- **报告导出**：当前维度 + 时间范围导出为 **CSV**（Excel）/ **Markdown** / **HTML**，头部附均值 / 峰值摘要。

### 4.8 Docker

容器清单：名称 / 镜像 / 状态 / 端口映射 / **CPU / 内存**（运行中容器经 cgroup 直读，首次轮询 CPU 显示 — 属正常，第二轮起为增量口径）。docker 未安装或 daemon 不可达时显示**不可用原因**，不报错。

- **容器退出告警**：运行中的容器意外退出（含被 OOM 杀掉）时写入事件历史并向全部启用的通知渠道推送；同一容器 1 小时内只报一次（抑制重启风暴）。面板没有「停止容器」按钮，手动 `docker stop` 也会触发告警——属已知行为。

### 4.9 端口占用

NAS 上所有被监听的端口：**端口 / 协议 / 进程（PID）/ 可达性**（可达 / 仅局域网 / 不可达），支持搜索与按可达性筛选。

- **一键释放**（管理员）：终止占用进程，二次确认；**系统关键进程受保护名单拦截**（操作被拒并提示 1004）。

### 4.10 风扇控制 —— 重点模块

> 前提：主板 hwmon 暴露可写的 PWM 通道；以下操作仅管理员。

- **接管总开关**：打开后面板接管调速；关闭（二次确认）交还主板 BIOS 控制。崩溃 / 升级重启后面板会自动对账接管状态，不会谎报。
- **风扇通道**：自动扫描主板 PWM 通道，未建风区的通道一键添加（默认只读监控，不干预转速）。
- **风扇卡**：转子动画按真实转速旋转（无转速计的通道按占空比估算，仅示意）；**PWM 开关**接管后可选**调速方式**——「定速」用占空比滑杆（下限 20%）手动控速，「曲线温控」按下方曲线自动调速；支持重命名、删除风区（删除即交还 BIOS）。
- **调速依据**：「曲线温控」的风区可在卡片「依据」下拉**手动指定温度传感器**（CPU / 主板 / NVMe / 硬盘实时读数任选），缺省为 CPU 最高温；例如机箱风扇可改绑最热的硬盘。机械盘休眠时该传感器无读数，持续失联会触发全速保护。
- **风扇曲线编辑器**：拖拽「温度 → 占空比」多点曲线，可增删节点；**迟滞**（回差温度，避免临界抖动）与**每轮斜率**（转速平滑变化幅度）可调；保存后按曲线自动调速。
- **安全保护**：温度传感器失联或温度到达临界值时，强制风扇全速（风扇失控保护优先于一切调速策略）。
- 转速每 2 秒实时刷新；所有写操作失败都会如实回显后端状态，不假装成功。

### 4.11 控制与自动化 —— 告警 · 通知 · 报告

三个页内页签 + 事件历史弹窗：

- **活动告警**：当前 firing 的事件列表（顶栏铃铛同源）。
- **告警规则与通知**：按指标（温度 / CPU / 内存 / 磁盘健康 / 阵列降级等）设阈值规则；配置**多通知渠道**——**Bark / Telegram / 邮件（SMTP）/ Webhook** 任意添加多个，规则触发时**逐渠道同时推送**（一规则可勾选多个渠道）；每个渠道可单独启停、编辑（凭据掩码回显，原样保存即保留旧值）与发送测试通知验证连通；触发 → 通知在后台发送，不阻塞采集。
- **报告导出**：一键生成整机健康报告（HTML），支持**脱敏导出**（内网 IP / MAC / 序列号打码），发群里求助不怕漏隐私。

### 4.12 操作手册 / 关于

- **操作手册**：面板内置的速览手册（带目录抽屉），离线可用。
- **关于**：当前版本、构建信息、**检查更新**（对比 GitHub 最新 Release）。

## 五、数据与配置存在哪？重启会不会丢？

| 内容 | 位置（应用数据目录 var/） | 升级 / 重装 |
|---|---|---|
| 历史数据库（SQLite） | `nasdeck.db` | **保留**，升级不丢 |
| 面板端口 | `port`（安装向导写入） | 保留 |
| 运行配置（日志级别 / 原始数据保留时长） | `runtime.env`（配置向导写入，白名单校验） | 保留 |
| 应用日志 | `app.log` | 持续滚动 |

卸载应用默认保留 var 目录（用户数据保护）；配置向导（应用「配置」）可随时调整端口、日志级别、原始数据保留时长，保存自动重启生效。

## 六、常见问题排查

| 现象 | 说明 / 处理 |
|---|---|
| 页面数据不动了 | 先看页头「最后更新」时间。cgi 反代形态不走 WebSocket，秒级数据以 2 秒轮询呈现属正常设计；持续不动去应用日志（var/app.log）看后端异常。 |
| 某块盘温度显示 — | 盘在休眠（正常，不打扰）；或 smartctl 未安装（看硬件检测页「运行环境自检」）。NVMe 温度经控制器探测，命名空间盘名自动匹配。 |
| 阵列卡后面的盘看不到自检按钮 | 这类盘系统里没有 /dev 节点，不支持在线自检——面板如实禁用，不是故障。 |
| 拓扑树里阵列的块设备出现在「直连」分组 | 阵列卡虚拟盘（VD）与物理盘之间无可靠对应关系，面板按直连盘如实展示其分区与挂载点，属已知设计。 |
| 历史趋势只有最近 2 小时 | 秒级原始数据默认保留 120 分钟，更长窗口走分钟 / 10 分钟聚合——聚合由后台任务滞后生成，新装实例需积累。可在配置向导调大原始保留时长。 |
| 风扇调速不生效 | ① 先确认已打开「接管」总开关；② 硬件检测页确认风扇驱动已加载、PWM 通道可写；③ 检查风扇线：4 针 PWM / 3 针 DC 接错口时主板可能不受控——这是硬件层面限制，面板如实回显。 |
| 告警没收到 | 控制与自动化页发一封「测试通知」验证渠道；规则阈值与比较方向（大于 / 小于）确认无误；通知在事件触发后的后台队列发送，慢渠道（邮件）有延迟属正常。 |
| 想看某功能为什么没数据 | 硬件检测页底部的**运行环境自检**实时列出每个工具 / 驱动的在位状态与生效配置。 |

## 七、版本与更新

- **关于页 → 检查更新**：对比 GitHub 最新 Release 提示新版本。
- 更新走应用中心升级流程：数据与配置全保留，数据库结构由面板启动时自动自愈。
