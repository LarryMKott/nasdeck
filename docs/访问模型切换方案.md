# 访问模型切换方案（安装/配置时选 CGI 反代 或 统一网关）

状态:**代码已实施(2026-10-09,待真机端到端验证)**。判定门槛 §1.1(48h watch.log)与
§1.3(X-Trim 头/前缀实测)尚未满窗;§1.2(入口热更新)未获用户确认——实施已按最稳妥
路径消化这三个未知:切换生效点在 cmd/main start(不依赖回调时机)、前缀剥离中间件对
剥/不剥两种转发均正确、鉴权信任边界编码进后端(uds 非空跳过 proxy_token)。
本文是实施记录与真机验证清单。

## 0. 背景

用户诉求：安装时让用户选择访问模型。现状是 CGI 反代单模型（fpk/README「访问模型」行），
唯一阻碍是 2026-08 真机教训「飞牛周期性清空第三方 gateway 入口 → 404」。

gwprobe 试验（`scripts/gwprobe/`，fpk/README「网关模式复核试验」节）：按现行官方文档方式
（ui/config 声明 gatewayPrefix+gatewaySocket）注册的网关入口，自 2026-10-08 23:02 起
持续 ALIVE。旧教训疑似源于旧版应用的非标准注册方式，现行标准方式未复现。

## 1. 判定门槛（全部满足才实施）

1. **watch.log 48h 无 ENTRY_CLEARED**（2026-10-10 23:02 满 48h，10-11 复查后卸载探针）。
2. **试验二·入口热更新**（零代码，用探针做）：改写
   `/var/apps/com.test.gatewayprobe/target/ui/config` 的 title → `appcenter-cli restart`
   → 用户看桌面图标标题是否跟随。验证 trim_http_cgi 是否实时重读 ui/config（决定切换
   逻辑能否放在 cmd/main start 里做「自愈式入口应用」，还是必须依赖安装期回调）。
3. **X-Trim 头转发证据**（用户点一次探针图标）：probe app.log 记录网关转发的身份头；
   同时确认转发到应用的 path 是否含 `/app/{appname}` 前缀（官方文档示例显示不剥前缀，
   实测为准——决定后端前缀剥离方案）。

若 1 不成立：不做切换，CGI 反代维持唯一模型（本文归档），探针卸载。
若 1 成立但 2/3 缺证据：先补试验再动工。

## 2. 两种形态总览

| 组件 | CGI 反代（现状） | 统一网关 |
|---|---|---|
| 桌面入口 ui/config | `url: /cgi/ThirdParty/{app}/index.cgi/` | `gatewayPrefix: /app/{app}` + `gatewaySocket: app.sock` |
| 后端监听 | TCP `127.0.0.1:9800`（可配） | UDS `${TRIM_APPDEST}/app.sock`（0660 root） |
| 转发链 | index.cgi 注入身份头 + 代理密钥 | trim_http_cgi 校验登录态后转发（含 X-Trim-*） |
| 请求路径 | index.cgi **剥**自身前缀 → 后端见 `/api/v1/...` | 文档示例**不剥**前缀 → 后端见 `/app/{app}/api/v1/...`（待 §1.3 实测） |
| WebSocket | 不可用 → 前端 2s 轮询 | 可用（nginx /app/ location 已配 Upgrade 头） |
| manifest | 省略 service_port、checkport=false | **不变**（网关忽略 protocol/port） |
| 信任边界 | proxy_token 共享密钥 | socket 文件权限（root 之外不可连） |

## 3. 实施设计（判定通过后）

### 3.1 切换的权威状态与生效机制

- 权威状态：`${TRIM_PKGVAR}/access_mode`，内容白名单校验后落盘：`cgi`（缺省）/ `gateway`。
- **生效点在 `cmd/main start`**（持有 TRIM_APPDEST、每次启动必跑、天然抗升级覆盖）：
  按 access_mode 把包内预置的 `ui/config.cgi` / `ui/config.gateway` 拷贝为
  `${TRIM_APPDEST}/ui/config`（注意路径用稳定前门，见 README「真机形态事实」）。
  避开 install_callback 的暂存目录陷阱；升级后整体替换包文件，下次 start 自动恢复所选形态。
- 安装向导 `wizard/install` 加 radio `wizard_access_mode`（cgi 默认）→ install_callback
  落盘 var/access_mode；配置向导同字段加「保持不变」缺省 → config_callback 落盘 +
  条件重启服务（重启即应用新入口）。
- 依赖 §1.2 结论：若 trim_http_cgi 不热更新入口，「改形态后需应用重启」就是设计内行为
  （config_callback 反正要重启；首次安装后系统注册入口的时机需真机看一眼）。

### 3.2 后端（backend/）

- `app/core/config.py`：新增 `uds: str = ""`（`NASDECK_UDS`）与 `gateway_prefix: str = ""`
  （`NASDECK_GATEWAY_PREFIX`，如 `/app/com.dashboard.nasdeck`）。
- `main.py` 启动分支：`uds` 非空 → `uvicorn.run(app, uds=...)`（不绑 TCP）；否则现状不变。
- **前缀剥离**（仅 gateway 形态）：ASGI 中间件在 `gateway_prefix` 非空时剥除请求路径前缀
  再进路由（静态文件挂载同样受益）。若 §1.3 实测网关会剥前缀，此中间件免掉。
- **鉴权边界**：`require_trim_auth` 现要求 X-Nasdeck-Proxy 密钥（防伪造）。gateway 形态
  index.cgi 不存在、无密钥头——UDS socket 权限即信任边界（等价强度），`uds` 非空时
  跳过 proxy 校验、X-Trim-* 直接采信。CGI 形态逻辑零改动。
- **index.html 资源前缀**（关键改造）：vite `base` 烤死在构建期而两种形态前缀不同，单
  dist 方案——构建用占位符 `VITE_PUBLIC_PATH=/__ND_PREFIX__/`，后端 statics.py 在回退
  index.html 时按请求路径替换占位符（含 `/index.cgi/` → cgi 前缀；以 gateway_prefix 开头
  → 网关前缀；直连 → `/`）。资产请求本身落在真实前缀下，两条转发链都到达后端静态挂载，
  无需双构建（保住包体）。

### 3.3 cmd/main（fpk/）

- 读 `var/access_mode`（缺省 cgi）：
  - cgi：现状不变（TCP 回环 + index.cgi）；
  - gateway：`export NASDECK_UDS="${TRIM_APPDEST}/app.sock"`、`export NASDECK_GATEWAY_PREFIX="/app/com.dashboard.nasdeck"`，
    就绪等待改 `curl --unix-socket .../app.sock /health`；启动前 `rm -f` 陈旧 socket、
    启动后 `chmod 660` + 属主 root（网关转发进程 UID 未文档化，先用 660 实测，不通再放宽）。
  - 两形态共用同一次 `ui/config` 应用（§3.1）。

### 3.4 前端（frontend/）

- `client.js apiBase()`：标记从 `index.cgi` 单一扩展为「`index.cgi` 或 `gatewayPrefix`」
  （gateway 形态 location.pathname 以 `/app/com.dashboard.nasdeck` 开头，取至前缀末尾）。
- `ws.js`：gateway 形态**启用 WS**（判定标记同上）——这是本特性的核心收益，
  2s 轮询降级仅剩 CGI 形态。
- `.env.fpk`：`VITE_PUBLIC_PATH=/__ND_PREFIX__/`（配合 §3.2 占位符方案）。
- 构建脚本 `scripts/build_fpk.py` 校验项同步（占位符存在性检查）。

### 3.5 升级与回退

- 升级：包文件整体替换 → var/access_mode 在 → 下次 start 恢复形态（与 port 镜像同款逻辑）。
- 回退：access_mode 写回 `cgi` + 配置页保存重启即回旧形态；网关形态全程不动 CGI 链路代码路径
  （分支隔离，缺省零行为变化）。

## 4. 测试矩阵（真机）

| # | 场景 | 通过标准 |
|---|---|---|
| 1 | 默认安装（cgi） | 行为与现状完全一致（回归基线） |
| 2 | 安装向导选 gateway | 桌面图标打开走 /app/{app}，面板正常，app.log 无 proxy 403 |
| 3 | gateway 形态 WS | 前端 WS 建立且实时推送（网络页秒级跳动不依赖轮询） |
| 4 | 配置页 cgi→gateway→cgi 往返 | 每次保存重启后桌面入口与面板均可达 |
| 5 | 鉴权（两形态） | 普通用户只读、写 403；无登录态直连 socket/端口被拒 |
| 6 | 升级（两形态各一） | 升级后形态保持、数据在 |
| 7 | gateway 形态改端口/日志等配置 | 与 cgi 形态一致 |
| 8 | 卸载重装 | 缺省回 cgi；@appdata 保留 |

## 5. 工作量估计

后端（UDS+中间件+占位符重写+鉴权分支）约 1 天；cmd/main+向导+回调约 0.5 天；
前端标记与 WS 约 0.5 天；真机双形态矩阵（§4）0.5-1 天。合计 **2.5-3 天**，
