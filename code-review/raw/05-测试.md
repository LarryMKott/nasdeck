## 一、测试数量核实

**结论：实测收集 223 条；静态 `def test_` 219 个；parametrize 展开仅 +4。"139 项"与当前代码树任何口径都不符，最可能是"14 个测试文件在缺依赖环境下收集失败"的历史运行结果（高置信推断，证据见下）。**

| 口径 | 数值 | 来源 |
|---|---|---|
| collected（parametrize 展开后） | **223** | `pytest --collect-only -v` 汇总行 "223 tests collected in 1.07s"（venv313 解释器 + 临时 pytest/pytest-asyncio） |
| 静态 `def test_` | **219**（async 111 / sync 108） | `Select-String 'def test_'` 于 tests/test_*.py |
| parametrize 展开 | **+4** | 仅 `test_alert_channels.py:28`（3 参数）与 `:63`（3 参数）两处装饰器，1 个用例各展开为 3 条 |
| 测试文件数 | **36** 个 `test_*.py` | `tests/` 目录列表；另有 conftest.py、__init__.py、fixtures/ 4 个数据文件。任务描述的"41 个测试文件"无法对应（36+2=38 个 py 文件，差距 3，无法定位口径来源） |

**139 差异解释（非 parametrize 原因）**：
- `backend/.pytest_cache/v/cache/lastfailed` 记录了一次历史运行中 **14 个测试文件以"文件级"条目失败**（pytest 约定：文件级条目 = 该文件收集/import 失败），另有 `tests/_dbg_test.py::test_debug_worker`、`::test_debug_drain` 两条节点级失败（该文件现已删除）。
- `.pytest_cache/v/cache/nodeids` 共 **225** 条 = 当前 223 条 + 已删除 `_dbg_test.py` 的 2 条。
- 这 14 个收集失败文件当前共含 **86** 条用例；225 − 86 = **139**，与宣称值精确吻合。
- 本人用无项目依赖的解释器（pyenv 3.13.13，缺 pydantic_settings 等）复现收集时，**报 ModuleNotFoundError 的正是同一批 14 个文件**（test_capacity_forecast、test_db_schema、test_downsampler、test_fan_failsafe、test_fan_schedule、test_history_query、test_ingest、test_logging、test_metrics_endpoint、test_p2_fixes、test_security_chains、test_selftest_schedule、test_smart_trend、test_storage_topology）。
- 推断：宣称的"139 项"来自一次依赖不全的运行（14 个文件 import 失败未计入）。缓存两个文件无法证明来自同一次运行，故此重建标注为**高置信推断**而非确定事实；确定的结论只有"当前树实测 223，与 139 不符"。

- 影响： storcli 版本差异或半截输出下解析结果不可知（兜底存在但无行为锁定）；rc≠0 带输出的采用分支回归不可知
- 建议场景：截断 PD 表、缺 SN/Model 节、serial 含 `"` 与 `<script>` 的输入断言 collect 不抛且字段降级；fake runner 返回 rc=1 有输出/无输出两态
- 优先级：P2

### P2-7 采集任务崩溃会炸整轮调速且无测试
- 位置：`app/services/control/fan_manager.py:381`（`temperatures()` 在逐区 try 之外）
- 证据：test_fan_failsafe 只测过 `_drive_zone` 直传 temps，从未测 `apply_tick` 在 `temperatures()` 抛异常时的行为

- 建议场景：monkeypatch `temperatures` 抛异常，锁定"整轮失败"或（更优）推动把采集移入保护块后断言降级行为
- 优先级：P2

### P2-8 test_smart_15m_tick_records_and_monotonic_day_marker 零断言
- 位置：`tests/test_smart_trend.py:154-160`
- 证据：两次 `await smart_15m.smart_15m_tick()` 后无任何 assert，测试名宣称的 records/幂等未验证

- 优先级：P2

### P2-9 报告 HTML 转义测试含恒真断言
- 位置：`tests/test_p2_fixes.py:124`：`assert "onerror=alert(2)" not in out or "&lt;b&gt;" in out or "onerror" in out.replace("<img", "")`
- 证据：第三个析取支在转义失败时恒为真（未转义输出含 `onerror`，`replace("<img","")` 不影响），整个 or 链在 img 注入未转义时仍通过
- 影响：`<img onerror>` 类载荷的转义回归不会被该测试捕获（前两个字面量 script/b 的断言有效）
- 建议场景：拆成逐字段精确断言（如 `"&lt;img" in out` 且 `"onerror=alert(2)" not in out` 单独成立）
- 优先级：P2

### P2-10 分级鉴权缺端到端接线测试
- 位置：tests/test_security_chains.py（全部直调 `require_trim_auth`）；`app/api/v1/*.py` 路由挂载
- 证据：无任何测试以 trim_auth=True 走 ASGI 客户端访问写端点验证 403；路由 `dependencies=[ApiKeyDep, TrimAuthDep]` 仅人工核对
- 影响：某路由重构时漏挂依赖不会被测试发现
- 建议场景：monkeypatch settings.trim_auth=True 后 `POST /api/v1/control/fans` 无头 → 403、带管理员头 → 200；GET 无 userid → 403
- 优先级：P2
